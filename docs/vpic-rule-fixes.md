# mcp.vin fixes to NHTSA's vPIC decoding rules

Generated by `scripts/vpic-rule-diff.mjs` from `data/vpic.db` (NHTSA vPIC release **2026_11**, built 2026-11-18T04:30:15Z). Do not edit by hand.

NHTSA's vPIC decoder turns a VIN into vehicle attributes with rule tables: each `pattern` row says that VINs of a WMI and model-year range whose characters match `keys` (VIN positions 4-8, then `|` and positions 10-17; `*` any character, `[...]` a set) have a value for one element (drive type, cylinders, ...). Vehicle-spec rows add values for a make, model and year from already decoded values (for example every "Launch Model" trim).

mcp.vin decodes VINs with NHTSA's own algorithm over NHTSA's monthly database, with the rule edits below applied at build time (`data-src/vpic-rule-fixes.jsonl`, `scripts/import-vpic.py`). Each edit names the exact NHTSA row it changes; when a new release changes that row, the edit is not applied and is reported for review. Every value a fix changes is shown with NHTSA's official value beside it.

The errors were found by comparing vPIC's decode of NHTSA's own crash-test and compliance-test vehicles with NHTSA's lab record of each vehicle (decode audit 2026-11-17), checked against EPA's configuration list; the evidence links are NHTSA's lab reports.

**26** fixes (26 applied, 0 need review), **34** row edits, correcting **33** decode errors.
